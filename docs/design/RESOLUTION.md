# 多尺度分辨率：低分辨率世界持续演化，聚焦处提高，过去不得事后冒充高分辨率

> 设计契约，尚未实现。本文只写设计，不改用户笔记、不改程序，不 build／test／typecheck。
> 用户原文：`docs/notes/note1.md:44-51`（`L45-46` 是全文唯一的诚实性底线），另涉 `L48`（模型只是近似）、`L49`（聚焦与回写）、`L51`（东周大部分低分辨率演化）。
> 同目录另两份契约：`docs/design/PRESENTATION-ABSTRACTION.md`（呈现怎么折叠与恢复）、`docs/design/LIVING.md`（角色为什么活着）。本文只解决一件它们都没解决的问题：**一段过去是以什么密度发生并被记录下来的**。
> 本文的每一节都以「现状」开头：写清仓库今天有什么、没什么。凡标「拟新增」的都是实现契约，不是已存在字段（沿用 `docs/design/LIVING.md:56` 的写法）。

## 0. 一句话

世界不是一直被精细演着。**大部分时间它只按几个聚合量往前走**（临淄十年只按人口、粮价、家族状态运行，`note1.md:46`）；玩家或呈现**聚焦**到某处时，那一处才「像一束光打进去」被提高分辨率（`note1.md:49-51`）。提高分辨率期间真发生的事要写进账本；**没有发生过的，事后不许生成出来当历史事实**（`note1.md:45-46`）。

这条底线不是道德要求，是**一条可以机械判定的规则**：查账本在那段时间窗口里有没有逐次记录。有，就是曾经高分辨率；没有，就只能说「这一段只有低分辨率的统计记录」。判定规则在 §4。

## 1. 两个词：分辨率与档位，不是一回事

先把最容易混的两个词分开。它们外观相似（都关于「细不细」），但一个**事前**、一个**事后**。

| | **档位** | **分辨率**（本文） |
| --- | --- | --- |
| 现状 | **已实现**：`shared/kernel/depth.js:14` `TIERS=['细演','普通','一笔带过']`，`:21` `ELIDED_NOTE='这里被省略了'` | **未实现**：`分辨率`／`低分辨率`／`高分辨率` 在 `shared/` 与 `docs/` 里 **0 处**（只有 `docs/notes/note1.md` 与两份审查、`ADJUSTMENT-PLAN.md` 自己提到） |
| 管什么 | 这一场**演多细**（文字厚薄、能看多深） | 这一段过去**以什么密度发生并被记录** |
| 单位 | 一场（`docs/数字世界 设计总稿 v3（草案） (2).md:145`「以『一场』为单位」） | 一段范围（一个时间窗、一块地方、一次聚焦） |
| 什么时候定 | **事前**：导师分算力时定（总稿 `:143`、`:145`） | **事后**：一旦发生就不再改，是这段历史的属性 |
| 能不能改 | 能：预算用完一档档往下降（`shared/kernel/depth.js:9`） | 不能：改的只能是**记录**或**模型**，不是「当年发生过什么」 |
| 改规则吗 | 不改：`shared/kernel/depth.js:3`「三档只改『文字厚薄』与『能看多深』，不改胜负规则」 | 不改：它只约束**呈现层能声明什么** |

**注意最后一行**：档位不改胜负规则，分辨率不改胜负规则 —— 两者都不动玩法。分辨率动的是**可信度**：它决定呈现在讲一段过去时，有没有资格说「这是这里发生过的事」。

`shared/kernel/depth.js` 今天已经做对了一件重要的事：`:11`「这个文件是纯函数：没有随机、没有时间、没有外部依赖」。本文要求的记录分辨率也必须是同样的确定性纯函数，答案只由账本内容决定。

## 2. 低分辨率世界怎样持续演化

### 2.1 承认 note1 的说法：按统计结构推进，不逐个演人

`note1.md:44`：「不是『加载地图』，而是实验室把一个模糊存在的城市重新提高分辨率。你会看到人群、街道、人物重新从统计结构中『显影』出来。」
`note1.md:46` 给了这组统计结构的具体名字：**人口、粮价、家族状态**。

**现状：这三个量在仓库里都不存在。** `shared/` 与 `web/` 检索 `人口`／`粮价` 命中 0 处。最接近的只有三类东西：

- **时间刻度已经全局存在**：`shared/kernel/kernel.js:19`「全场的默认起始天数（围城的时间刻度）」、`:42` `root = holder.kernel || (holder.kernel = { days, flags: {}, worlds: {}, current: null })`。所以「过了十年」这个刻度有地方挂，缺的只是「这十年里世界是什么样」。
- **「世界真的变了」已经有了签名机制**：`shared/kernel/kernel.js:117-130` `pulseSignature(world, event)`，签名由 `days／flags／ctrl／noticed／places／lastAct` 拼成；`:564` 用它判断 `changed`，`:571-574` 变了才落一条 `world.pulse`。**这是本仓库已有的、最接近「低分辨率世界记录」的东西** —— 它就是「某一刻世界状态的紧凑记录」。
- **逻辑拍已经有了**：`shared/life/life.js:1`「一秒一个整数逻辑拍」，`:151-198` `runTick`。

### 2.2 拟新增：一组低分辨率状态量与它的推进方式

**状态量（每个 scope 一组，最小可行）：**

| 量 | 形状 | 说明 |
| --- | --- | --- |
| `人口` | 一个数 | 这一处有多少人。升落按粮价与时间算 |
| `粮价` | 一个数 | 缺粮则涨。涨落按人口与外部条件（围城、巡灯、更鼓）算 |
| `家族状态` | 每个家族一个分量 | `note1.md:46` 点名的第三个量。家族之间的位置变化是「显影」时最先看得见的东西 |
| `天数` | 一个数 | **已有**：`shared/kernel/kernel.js:19`、`:42`、`:119`。不新增 |

前三个是「拟新增」，不得当成已有字段引用。

**推进方式（复用现有逻辑拍，但不逐人演）：**

- 走同一个整数逻辑拍（`shared/life/life.js:1`），每个 scope 每 N 拍推进一步。
- **不进入逐人循环**：即**不走** `shared/life/life.js:174-184` 的 `people` 循环（每 `cadence` 拍给每个人落一次 `think`），也因此**不走** `:179-182` 的 `dispatch`。后果是：不调 `perceive／hear／tick`、不写 `actor.*`、不产生逐人感知。
- **落一条低频记录**：聚合量真的变了才落，用与 `shared/kernel/kernel.js:117-130` 同族的签名。频率大约是「每 N 拍」或「量真的变了」，**不是每人每拍一条**。

**规模对比（这是它为什么不算「偷偷烧算力」的核心理由）：**

| | 逐人演 | 低分辨率推进 |
| --- | --- | --- |
| 每拍工作量 | O(在场人数) | O(scope 数)，与在场人数**无关** |
| 是否调 LLM | 深层角色会（总稿 `:311`） | **不调**，纯确定性算术 |
| 账本条数 | 每人每反应一条 | 每 scope 每 N 拍至多一条 |

### 2.3 记录与存档的边界

- **事实只在账本，记忆只留账本 seq 与派生量**（`docs/KERNEL.md:292`）。所以「十年里临淄是什么样」这件事，唯一的合法载体是账本上的低频记录，不是任何内存里的对象。
- 账本只追加；`payload` 的字段顺序参与 hash（`docs/KERNEL.md:18`）。新增记录种类必须**默认不写**，开关关闭时旧路径字节不变（`docs/KERNEL.md:207`、`:236` 的既有规矩）。
- 存档走 `shared/engine/session.js:207-217` `save()`：它存账本、主张图、导师／导演／心智状态，再 `...state`（含 `episode` `:45`、`designs`、`predictions`）。世界层状态在 `shared/kernel/kernel.js:41-42` 的 `holder.kernel`。**低分辨率聚合量应该落在这两处之一，而不是新开一个存档区。**

## 3. 聚焦：开始、结束、回写

`note1.md:49`：「聚焦的地方才有更精细的高分辨率模型，**结合低分辨率模型推进世界，同时更新低分辨率世界**。」
`note1.md:51`：「东周世界大部分以低分辨率演化，实验室聚焦的地方**就像一束光打进去**，有高分辨率。」

### 3.1 开始条件（三条同时成立）

1. **有人真的要看向这里**：玩家走进这一处、追问某个人、或某个呈现需要这一处的细节（`note1.md:49-51`「一束光打进去」）。
2. **这一处在低分辨率里有记录**：§2.2 的聚合量与签名在账本上存在。**没有记录就没有「显影」可言** —— 这正是 `note1.md:44`「从统计结构中显影」的字面含义：光打进去，照见的是**已经在那里的统计结构**，不是凭空生成的城市。
3. **导师为这一处分配了算力**：总稿 `:143`「算力有上限，分给哪个导演、哪一场，决定一个呈现里的人活得有多细」；`:145` 档位「以一场为单位」；预算不够就降档，降到底照常演完（`shared/kernel/depth.js:9`）。

### 3.2 结束条件（任一成立）

1. **聚焦范围收束**：这一场结束、离开这一处、或只读镜头合上。
2. **预算用完**：从「细演」一档档降到「一笔带过」，降到底也照常演完，画面标 `这里被省略了`（`shared/kernel/depth.js:9`、`:21`）。
3. **已有一个确定结果**：这一处已经能给出结论，不必继续演（`docs/design/PRESENTATION-ABSTRACTION.md:20`「若原过程未留，只恢复结果」）。

### 3.3 回写：允许改什么、不许改什么

`note1.md:49` 要求「同时更新低分辨率世界」，所以聚焦**必须**能回写。但回写的边界必须写死，否则 `L45` 会被从后门绕过。

**允许（回写＝新事实入账＋聚合量前进）：**

- 聚焦期间**真的发生**的事实进账本：`actor.act`／`actor.react`／`claim.*`／`world.pulse`，带真实 seq。
- **聚合量的当前值随之前进**：因为世界真的过了一段时间，人口／粮价／家族状态应当反映这段时间。
- 聚焦窗口的**起止边界**本身记一条（这样以后才查得出「哪一段是高分辨率的」）。

**不许：**

| 不许 | 为什么 | 依据 |
| --- | --- | --- |
| 用聚焦期间的结果**追认**低分辨率期间没发生过的事 | 这就是 `L45-46` 的十年例子 | `note1.md:45-46`；本文 §4 |
| 把「只算出来的」（确定性派生）写成「发生过的」 | 恢复身份被混用 | `docs/design/PRESENTATION-ABSTRACTION.md:58` 三种身份 |
| 改写别的呈现已有的主张 | 呈现只能「读取视角范围内的主张；通过动作产生新主张」 | 总稿 `:69` |
| 为看一眼而重新分配、重新 dress、重新 meet | 阅读／展开／手摇属**呈现操作**，不得再调 `perceive／hear／tick` | `docs/design/PRESENTATION-ABSTRACTION.md:34` |
| 把折叠当成删除 | 「折叠不删除事实」 | `docs/design/PRESENTATION-ABSTRACTION.md:54` |

**一句话**：回写不是「把过去重新演一遍」，是「**聚焦期间的新事实进账，聚合量继续往前走**」。过去那一段本身一个字都不改。

## 4. `L45` 的判定规则：哪条记录算「曾经高分辨率」

这是本文最重要的一节。

`note1.md:45`：「**被低分辨率模拟过的过去，不能后来假装自己曾经被高分辨率模拟过。**」
`note1.md:46`：临淄十年只按人口、粮价、家族状态运行；十年后**不能**突然生成「某人在第七年六月某日下午和妻子发生了这样一场对话」，然后把它当成历史事实 —— 「因为这件事实际上没有发生在模拟中」。

### 4.1 四条判据（同时成立，才算「曾经以高分辨率发生」）

| 判据 | 内容 | 依据 |
| --- | --- | --- |
| **R1 当时写下的逐次记录** | 账本上有那段时间的逐次记录（`actor.act`／`actor.react`／`world.pulse`／`claim.*`），带真实 seq。**事后算出来的不算** | `docs/KERNEL.md:292`「事实只在账本，记忆只留账本 seq 与派生量」；`docs/KERNEL.md:18` 账本只追加、hash 对字段顺序敏感 |
| **R2 有聚焦窗口的边界** | 那段范围有明确的开始与结束，而不是「整天整年都在演」。窗口之外的时间只按聚合量走 | 现成先例：`shared/engine/session.js:123-138` 的一段经历有 `from`／`to`，`:45` 挂在存档 state 上 |
| **R3 记录指的是「某一件事」** | 能指到**具体的人 + 具体的动作 + 具体的时刻**（有 person、有 act、有 seq 或 tick）。**由聚合量差分出来的东西不算** | 对照 `shared/kernel/kernel.js:117-130` 的签名是「一组数的压缩」，它证明发生过什么，不证明**谁做了什么** |
| **R4 没有被标成「没演出来」** | 被「一笔带过」处理、带 `这里被省略了` 标记的那一段，不算高分辨率 | `shared/kernel/depth.js:7`、`:21`；总稿 `:149`「没有分到算力的地方不会演出来。**没有演出来，就没有事实**」 |

R4 的依据是总稿里现成的一句话 —— 它本来就是 `L45` 的同类表述，只是从来没被当成判定规则用过。

### 4.2 判定函数（拟）

给定 `(scope, 时间范围)`：

| 查账结果 | 结论 | 允许做什么 |
| --- | --- | --- |
| 有满足 **R1–R4** 的逐次记录 | 「这一段**曾以高分辨率发生**」 | 按 `PRESENTATION-ABSTRACTION.md:58` 第一种身份**原材料再呈现**（纯读） |
| 只有 §2.2 的聚合记录 | 「这一段**只有低分辨率的统计记录**」 | 按 `:58` 第二种身份**确定性派生重建**，给出聚合曲线／摘要；**不得**生成逐人逐日事件，**不得**把它写成历史事实（`:20`「若原过程未留，只恢复结果，**不演假调配**」） |
| 连聚合记录也没有 | 「这一段**没有留存**」 | 诚实显示（`:60`「删了原文、资产或 trace 就诚实显示…」；`:26`「不承诺当前记录都足以恢复场景或声音」） |
| 玩家想看「如果当初细演会怎样」 | 这是**分支**，不是历史 | 只能走 `:58` 第三种身份**独立分支重演**：显式标注、由原回放引擎在隔离分支执行、**不回写主世界**（`:58`；`note1.md:292`「一个呈现只是对世界发展进行了约束」） |

### 4.3 三个最容易混的动作，必须分开写

这是 `L45` 的可判定形式 —— 争的从来不是「能不能重建」，而是**哪一种重建**：

| 动作 | 材料要求 | 允许吗 | 依据 |
| --- | --- | --- | --- |
| **重建** | 当初留有材料，**或**能由已留存输入 + 派生规则版本**确定性派生** | **允许** | `PRESENTATION-ABSTRACTION.md:58` 前两种身份；`:60`「『随时重建』的前提是保留对应材料与规则版本」 |
| **补写** | 无 —— 凭空生成一段没人演过的过去 | **禁止** | `note1.md:45-46`；`PRESENTATION-ABSTRACTION.md:20` |
| **分支重演** | 宿主已有回放入口 | 允许，但**隔离且标注** | `PRESENTATION-ABSTRACTION.md:58` 第三种身份 |

「补写」违反的不是一条审美要求，而是 `docs/design/PRESENTATION-ABSTRACTION.md:54`「**折叠不删除事实**」这条既有原则的对偶：既然折叠不删除事实，那么**恢复也不得创造事实**。

### 4.4 模型变准 ≠ 过去被演过（直接回答 `note1.md:48`）

`note1.md:48`：「本质是高分辨率的模型保有更丰富的信息，低分辨率少很多，而且只是近似，**需要不断完善**。」

**允许**模型变准：低分辨率模型可以越来越好。
**不**允许因为模型变准了，就把当年的记录说成当年演过。

改善的是**模型**，不是**往事的身份**。这一条必须单独写出来，因为它是「不断完善」这句话最容易被读成「反正以后会算出来」的地方。

### 4.5 `L312` 的措辞（采用调整计划给的建议，不自创）

`note1.md:312` 末句：「底层的信息只要需要，就能随时重建。」
照字面执行会撞上 `L45`（详见 `docs/notes-review/design-reading.md` 的 T1）。建议统一采用 `docs/design/ADJUSTMENT-PLAN.md:34` 的措辞：

> **「底层的信息，只要当初留有材料、或能由已留存输入确定性派生，就能随时重建。」**

**为什么这句和 `L45` 不打架**：它把「重建」限死在**材料**或**确定性派生**两条路上。而「假装曾被高分辨率模拟过」两样都没有 —— 它不是重建，是补写（§4.3）。限定词不是让步，是**把 `L312` 从一句愿望变成一条可执行的规则**。

### 4.6 与呈现契约的对齐检查（逐条，不能打架）

| 呈现契约 | 本文对应 | 是否一致 |
| --- | --- | --- |
| `:20` 原过程未留，只恢复结果，不演假调配 | §4.2 第二种输出 | 一致 |
| `:54` 折叠不删除事实 | R1 要求记录留在账本；折叠只改「看不看」 | 一致 |
| `:58` 三种恢复身份 | §4.2 的四种输出与之逐条对应 | 一致 |
| `:60` 「随时重建」的前提 | §4.5 的限定措辞 | 一致 |
| `:64` 新版本只作 pending 提示，仍能返回可留存的旧版 | 高分辨率记录不因新版本被改写 | 一致 |

## 5. 和 `shared/kernel/depth.js` 三档位怎样共存（不删档位）

**结论：两件事，不是一个东西的两种粒度；它们共存，档位保留。**

- **档位**回答：「这次呈现花多少算力？」（事前、按一场、只改厚薄，`shared/kernel/depth.js:1-3`、`:14`）
- **分辨率**回答：「这段历史以什么记录存在过？」（事后、按一段范围、决定呈现能声明什么，本文 §1、§4）

三条关系，双向但不重叠：

1. **档位是分辨率的一个输入**：这一场按「细演」演完 → 这一场带着逐次记录进账本 → **这一段是高分辨率**；按「一笔带过」演完 → 只剩摘要 → 这一段是低分辨率。
2. **但档位 ≠ 分辨率**：细演只让**这一场的时间窗**变高分辨率，不会让同期的其他地方、其他时间跟着变高。`L45` 管的是后者。
3. **分辨率不反向改档位**：一段历史曾经是低分辨率，**不**导致未来的某一场被降档。未来演多细，仍由导师分算力决定（总稿 `:143`、`:145`）。

**实现建议（不删档位、不动默认行为）：**

- `shared/kernel/depth.js` 继续只管「演多细」，本文不改它的任何语义。
- **拟新增**一个并列的**记录分辨率**字段，挂在①账本记录、②一段经历的 scope 上。挂点现成：`shared/engine/session.js:45` 的 `episode`、`:123-138` 的边界计算已经是「一段范围」的模型。
- **默认不写**：开关关闭时存档形状与账本字节不变（`docs/KERNEL.md:207`、`:236`）。这是本仓库的既有规矩，不是本文新提的要求。

## 6. 和 `docs/design/LIVING.md` §11 的冲突怎样并存

**现状**：`docs/design/LIVING.md:171` 写「不承诺**后台世界推进**、自由生成对话、真算力计费、角色游历，或所有幕同时自发行动。」
**本文要求**：低分辨率世界**持续演化**（§2）。

两句看起来顶上了。拆开三个词就不顶：

| 词 | 含义 | 做不做 |
| --- | --- | --- |
| **后台推进** | 玩家不在场时，宿主**主动跑演出**（逐人感知、决策、写账） | **仍不做**（`LIVING.md:171` 原文保留其约束力） |
| **状态持久** | 世界状态存得住、读档接得上 | **已有，且必须有**：`shared/engine/session.js:207-217`；`shared/kernel/kernel.js:41-42` |
| **低频演化** | 低分辨率世界按聚合量往前走，**不逐人演、不调 LLM、只落低频记录** | **这就是本文要的**（§2） |

**为什么这不是偷偷承诺后台烧算力：**

1. **复杂度不同**：逐人演是 O(在场人数 × 拍数)；聚合推进是 O(scope 数 × 拍数/N)，**与在场人数无关**（§2.2）。
2. **不需要 LLM**：聚合推进是纯确定性算术；总稿 `:311` 明写「LLM 不逐帧决策」，所以它连调用口都没有。
3. **它本来就必须存在**：没有低分辨率记录，就**分不清哪一段是高分辨率**，`L45` 的判定规则（§4）无从执行 —— 判定规则查的正是「那段时间窗口里有没有逐次记录」。
4. **边界写死**：不预演玩家未到场时的**具体事件**（那直接违反 `L45`），只推进聚合量与写低频记录。

**建议改法（本文不改 `LIVING.md`，写在这里由 captain 另派任务）**：

把 `docs/design/LIVING.md:171` 的
> 不承诺后台世界推进、自由生成对话、真算力计费、角色游历，或所有幕同时自发行动。

改成
> 不承诺**后台烧算力的世界推进**（玩家不在场时不主动跑演出）、自由生成对话、真算力计费、角色游历，或所有幕同时自发行动。**低分辨率世界按聚合量持续演化不在此列**：它不逐人演出、不调用 LLM、只在账本上留下低频统计记录，见 `docs/design/RESOLUTION.md`。

## 7. 判据（用 `note1.md:46` 自己的例子，可复验）

- **情形**：临淄按低分辨率跑了十年，账本上只有人口／粮价／家族状态的低频记录。十年后玩家聚焦回临淄。
- **合格**：聚焦**之后**新发生的事逐次记录、进账本、被呈现；聚合量从此往前走（§3.3）。
- **不合格**：生成「某人在第七年六月某日下午和妻子发生了这样一场对话」并当成历史事实（`note1.md:46`）。
- **怎么机械判**：查账本第七年那个窗口内有没有满足 R1／R3 的逐次记录。**没有** → 只能输出「这一段只有低分辨率的统计记录」，并按 `PRESENTATION-ABSTRACTION.md:20` 只恢复结果。
- **接口形态（拟，不新增必填字段）**：一个只读判定入口，入参 `(scope, 时间范围)`，出参四种结论之一（§4.2）。**它必须是只读的**：不能因为「查了一次」就写账、写记忆或调 `perceive`（`PRESENTATION-ABSTRACTION.md:34`）。

## 8. 尚未实现（诚实边界）

- **本文只是契约。** 仓库里没有低分辨率世界、没有聚焦提高分辨率、没有分辨率判定入口。`分辨率`／`低分辨率`／`高分辨率` 在 `shared/` 与 `docs/` 里 0 处。
- **人口／粮价／家族状态三个量不存在**：`shared/` 与 `web/` 检索 0 处。
- **账本记录里没有「这段是以什么分辨率发生」的字段**。现有最接近的两样东西是 `shared/kernel/kernel.js:117-130` 的 `pulseSignature`（世界状态的紧凑签名）与 `shared/engine/session.js:45`／`:123-138` 的一段经历边界 —— 都只提供了一半。
- **没有可点击原型**，也不承诺「所有低分辨率时段都能被判定」：若聚合记录本身没留，只能落到 §4.2 第三种输出。
- 本文不改 `docs/design/LIVING.md`、总稿、`docs/CONTRACT.md`、`docs/notes/note1.md` 或任何代码文件；需要改的都在 §10 列出。
- 未 build／未 test／未 typecheck（本仓库规矩：成员不跑仓库测试）。

## 9. 不做什么

- **不把分辨率做成渲染概念**（不是 LOD、不是画质档）。它管**记录与可信度**，不管画面精度。
- **不做数值面板／柱状报表／网页卡片**：聚合量不出现在普通界面，只在 `?dev=1`（`docs/HANDOFF.md:17`；`docs/design/LIVING.md:71`）。
- **不做后台烧算力的世界推进**（§6 第一个词）。
- **不预演玩家未到场时的具体事件**（直接违反 `L45`）。
- **不自动补齐已丢失的低层材料**（`PRESENTATION-ABSTRACTION.md:104`）。
- **不设计冷存储、归档、轨迹删减、版本迁移**（`:60`、`:104` 已划出去）。
- **不删掉 `shared/kernel/depth.js` 的三档位**（§5）；也不改它现有语义。
- **不做真实算力计费**：本文只说「算力有限、要分」（总稿 `:143`），不碰钱。
- **不新增必填字段**：一切新增默认关闭，关闭时旧对照组与存档字节不变（`docs/KERNEL.md:207`、`:236`）。
