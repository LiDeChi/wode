# 呈现的抽象与折叠：少用注意力，需要时恢复低层

> 全媒介设计契约，尚未实现。本轮仅写设计，不改用户笔记或程序，不 build／test／typecheck。
> 用户原文：`docs/notes/note1.md:1`。它讨论所有呈现怎样压缩现实，与文本渲染器没有派生关系。中文排版另见独立文档 `docs/design/TEXT-RENDERER.md`。

## 1. 原则：把关注的对象提高一层，保留下去的路

任何呈现都可以折叠：一台机关的运转、一场调配、一个人的行动、一段场景、声音或文字。折叠后仍表达玩家此刻关心的高层事实，必要时能恢复对应低层材料；不是把一切藏进“摘要 → 文本详情 → 账本”。恢复可以是展开机关、手摇一次真实经过、放回当时场景、听见当时的声音、比较两次姿态，也可以是阅读。

初见时，玩家可能愿意看导师如何分配、导演如何安排、演员怎样接住刺激；熟悉后，只想知道“这次有什么不同”。呈现应该记得他的观察选择，支持把重复过程合上，把有限注意力交给新的关系与后果。不能把熟悉解释成不再允许深入，也不能通过强迫播放完整过程来证明系统在工作。

总稿把电影、游戏、科研看作同世界的不同观察方式（`docs/数字世界 设计总稿 v3（草案） (2).md:105`），把片场与笔记视为记录的呈现（同文件 `:255-260`），并要求视图与摘要可重算（同文件 `:694`）。本契约把这个原则扩展到每一个呈现尺度；保留装置与实物，而非报表面板（`docs/design/LIVING.md:58-71`）。

## 2. 抽象不是少显示几个字

一个呈现单元包含：关注对象、可见范围、表达的结论、低层组成、真实来源、恢复方式。高层要回答一个更大的问题，而非截断低层内容。不同尺度可以继续向上组合；不能把范围不完整的材料包装成全局结论。

| 关注尺度 | 展开时 | 熟悉后折叠成 | 按需恢复 |
| --- | --- | --- | --- |
| 导师一次调配 | 几盏灯分别落到各场，油壶与灯芯显示已分配和细密程度 | 这场的灯芯与一个有来处的“安排未变／有一处改变” | 玩家点灯，展开当时分配器物；若原过程未留，只恢复结果，不演假调配 |
| 导演一拍安排 | 预测牌、真实木签、批注、节奏栓的相互关系 | 一个栓住或松开的节奏机关；改变时露出新批注的纸边 | 点纸边或手摇预测牌与木签的对照；可以读当时说法，但不是唯一恢复方式 |
| 演员一次反应 | 铜槽中的吸收、余流、停层与动作闸分别出现 | 身段、停手或已经发生的行动；随身经历扣片 | 点铜纽展开当次三层槽；看下一环的真实行动与谁接收；缺 trace 不画水路 |
| 一场经过 | 人、物、灯光、声响与事件连续出现 | 场中结果及仍可争议的关系；器物保留后果 | 电影手摇到对应片段、在实验分支重看当时场景、读一段记录或听留存声段 |
| 多场的经历 | 每场自己的条件、反应和后果 | 同一人留下的变化，或一条仍有缺口的历史关系 | 展开到子场景，再恢复其可用材料；不是拿最近几条感知当完整历史 |

这些是可选的表现方案，不承诺当前记录都足以恢复场景或声音。声音只在确有留存片段／原资产与拍序时恢复；姿态可以从留存的派生量重建；文字可作为补足渠道。渠道之间可互补，但不能拿另一个媒介掩盖缺失事实。

## 3. 玩家掌握折叠，导演安排表达

导演可以给默认尺度与建议恢复入口，玩家决定看多深。每个可见呈现都有可达的合上／展开入口；隐藏的过程仍能从原物或“我的观察方式”找回。现场入口可以很小，但不能彻底消失或只在 hover 时出现。

玩家可逐对象选择“看完整经过／只看结果／只看变化”，也可把一类重复过程收起。初次打开可以邀请看一遍，不能把教程变成必须看完的流程。重复到访只沿用玩家已经作出的选择；首版不根据次数、停留或档位自动判断“他懂了”，更不改导师对玩家的理解。

阅读、听取、展开、折叠、手摇已留存的经过都属于呈现操作。它们不能再调用原演员的 perceive／hear／tick，不能调用会写 user.ask 的询问，不能为看灯油而重新分配，不能为看手稿而再次 dress。现有 watch 会登记观察，不能借其执行自动恢复（`docs/design/LIVING.md:75,133`）。真正“追问”“改安排”“再试一次”必须是另一组明确的世界操作。

折叠偏好、未读变化、播放位置与镜头观察状态在呈现层保存，不写角色记忆、主张图或 watched／asked。展开不默默暂停世界；宿主保留明确的暂停操作和当前暂停状态。无障碍模态浮层可隔离玩法键，是否继续生活拍仍由原宿主时钟处理。

## 4. 特殊变化才值得再看一次

“变化”必须有新旧真实材料，不能只是 seq 变了、动画重播了或计时器跳了。首版可以标出的变化：所选档位改变、导演 learn 的 before／after 有差异、实际 actor.act、新的接受／拒绝、主张变成 former／disputed、真正收束、恢复材料缺失。正常激活衰减和火焰摆动是已知过程，不不断提醒。

变化先显在原物上：灯芯粗细不同、手稿多了一道批注、经历扣片多一道刻痕、旧绳松开。附一个可折叠的“有一处改变”入口，不默认放大镜头、不突然播完整调配、不开文本弹窗、不盖住玩家手里的操作。声音提示可关闭，且必须有视觉／可读屏的等价入口；不把警告做成只能靠颜色辨认的红点。

玩家点变化入口后，先看到“哪件事与上次不同”，再自选恢复媒介与尺度。若只有角色当时的理由而没有确定因果，标成“他当时这样说”；若缺旧值，就只说“有新记录”，不宣称“比上次更好”。阈值未定义就不造“算力不足”；灯油的 spent 目前是分配量，不是实时消耗（`docs/design/LIVING.md:52,67`）。

玩家可以关闭一类提示；未读变化在相应器物目录保留。真正的机会／危险仍由宿主现有规则产生，合上提示不阻止结果；现场可保留一个极小的状态入口，不能用长通知强制夺回注意力。“等你”与期限不能靠形容词混同，当前语义偏差见 `docs/design/LIVING-autonomy-audit.md:51-53`。

## 5. 恢复低层的真实性

每个单元及其派生结论带 scope、来源和覆盖范围；来源可在开发层核对，普通玩家默认通过机关、动作与当时记录理解。不要求每次展开都展示 seq 或账本。

- scope 至少分开世界、episode、分支／实验、视角、电影录制；裸 seq 不能跨世界当唯一键。
- 事件引用使用真实 seq 与所读字段；cause 只沿已有边。结构化状态派生引用留存快照或当时输入、派生规则版本与字段路径；没有事件 seq 时不编一个。
- 高层单元保留子单元 id、来源集合和 coverage。折叠不删除事实；上层的争议、设想、局部覆盖与缺口不能被一句肯定结论抹掉。
- 原文和声段从已有可见呈现记录／资产读取；原文的繁简、渠道和当时说法身份保留。呈现缓存不回填角色记忆，严格版不把 line／appeal 原文塞入 minds 或 life.store；它们只是按原可见记录被展示。
- 动态字段只有当前值时只能表现“现在”，不能冒称“当时”。trace 必须当时留存；当前记忆不能倒算过去（`docs/design/LIVING.md:62,98,111,141`）。

恢复有三个明确身份：**原材料再呈现**（同一记录／资产／快照）、**确定性派生重建**（同一输入与版本产生姿态、机关或摘要）、**独立分支重演**（需宿主已有回放／实验入口与明确标签）。前两者纯读；第三者由原回放引擎在隔离分支执行，不能由折叠控件重演原世界。渲染器不自行创建分支、重放命令或生成缺失声音。

“随时重建”的前提是保留对应材料与规则版本。删了呈现缓存可重建；删了原文、资产或 trace 就诚实显示“这一段只有动作记录／原声没有留存／只保留了摘要”，可继续恢复仍有的部分。本文不设计冷存储、轨迹删减、资产归档或版本迁移；需要这类能力另立任务。电影 v1 只有输入记录，其旧语义不被新折叠承诺覆盖（`web/film/format.js:1-3,24-42`）。

## 6. 动态呈现不会夺走正在观察的东西

稳定键为 scope＋subjectId＋unitId。展开的内容固定 capture／revision、镜头锚点、页码或播放位置；新版本只作为 pending 提示。玩家选择“看后来的”才更新，仍能返回可留存的旧版。切场后标明仍在看上一场；换分支另存观察状态，不能把上一人的展开移给列表同一位置的下一人。

没有实质变化不重复排队；批量 DOM／器物更新只是表现更新，不是逻辑拍。开合不重置焦点、滚动、选中、音量或回放进度。恢复当前器物位置可微调布局，但不能为了自动对齐把相机拉走。主动播放恢复片段需有停止／返回控制；合上停止该呈现声段，不改变世界声音事件或演员感知。留存声音提供已有的文字／动作等价说明，留存动画可逐步看静态关键帧；等价材料同样回指来源，不凭可达性要求补造台词。

键盘与触控都有同名入口，3D 拾取有 DOM 等价入口，目标至少 44×44px。模态时焦点留在观察区，关闭回到原器物入口；玩法 Enter／空格不接收展开键。长文原生滚动；场景观察滚轮／触控不穿透为玩法。reduced-motion 以静态关键姿态、槽层与文字／声音选择代替强制动画，不降低证据完整性。

## 7. 跨四种呈现的共同边界

| 呈现 | 高层默认 | 可恢复的低层与边界 |
| --- | --- | --- |
| play | 眼前人、物与实际后果；重复调配合在案上 | 真实铜槽、经历、当拍设计；纯观察不改生活拍，不制造 NPC 行为 |
| hub | 灯芯、笔记压条、手稿批注 | 原分配结果／笔记来源／当时对照；不重新 meet 或分配；现有器物依据 `web/hub/records.js:19-79` |
| film | 已录制片段的意义与变化 | 手摇放映、当时姿态／声音／来源；只操作该录制的隔离世界，不增加主世界记忆 |
| lab | 锁定条件下哪一处不同 | 两条试验各自的机关、场景、感知和因果材料；查看不再拉杆或运行实验，不串主世界 |

共同数据契约（拟新增，非要求本轮实现）：

```js
PresentationUnit = {
  id, subjectId, scope, revision, capture,
  conclusion, refs, coverage, children,
  forms: [{ id, medium, availability, materialRefs }],
  restore: [{ id, formId, mode: 'retained'|'derived'|'branch-replay' }]
}
// medium 可是 device / pose / scene / sound / text；不强制每单元全有
// 纯读接口：readUnit(id,capture)、readMaterial(ref)、compare(before,after)
// 本地观察接口：setDepth(id,depth)、openForm(id,formId)、closeForm(id)
// branch-replay 只是指向宿主已有回放入口，不由这些接口执行世界命令
```

共用的是身份、可见范围、折叠偏好、变化证据与恢复约束；不同媒介保留自己的表现器，不用一个“大渲染器”包办 Three、音频、电影引擎和文字。默认文字译述不等于结论本身。首版不采用 LLM 自动总结，也不替导师／导演设计资源调度。

## 8. 最小原型与互斥接线

先在已有的导演案或导师灯油选一件原型：一个高层结果、两次真实留存输入、一个可折叠器物过程、一条特殊变化和一项缺材料情形。玩家第一次能看完整关系，合上后只看结果；换到新材料仅出现纸边／灯芯变化，主动展开才恢复对应低层。至少用器物或姿态恢复一次，文字仅补清含义，不把原型做成三层阅读组件。离线样例必须标“演示材料”，只有接入真留存记录后才称真实调配。

未来任务先明确共用契约与该原型唯一目录，再并行分配 `web/play/**`、`web/hub/**`、`web/film/**`、`web/lab/**`；各页面接各自已有只读材料，不能各改 shared、用户 note 或别人的目录。公共身份／观察状态模块需单一负责人，文本模块按独立 TEXT-RENDERER 任务维护。首个原型不能顺手扩成所有页或资源调度实现。

主 Agent 后续验收：收起灯油过程，只看结果；换一次有出处的 chosen 后看见对应变化；展开当时灯油结构而非文本账本；合上再开保持位置，重复打开同一 capture 的 save／账本不增长。缺分配过程就只显示现存结果。film 恢复只读其分支，lab 查看不再试验，play 看铜槽不再感知；变化与原材料在普通／开发模式同源。

当前能审阅的是上述全媒介抽象契约与例子，还没有可点击原型。不支持自动认定玩家熟悉、自动补齐已丢低层、任意场景／声音历史重建、冷存储与归档实现、真实算力计费、后台世界推进或资源调度。本契约保护的是“少看而不失去下去的路”，不承诺尚未留存的路存在。
