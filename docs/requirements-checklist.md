# 数字世界第一版需求与验收清单

依据：[《数字世界 设计总稿 v3（草案）》](<数字世界 设计总稿 v3（草案） (1).md>)，核对日期 2026-10-11。章节号沿用设计稿。史料依据另见 [history-sources.md](history-sources.md)。

以前只有设计稿，容易把“首版要演示的东西”和“以后世界能长成什么”混成一次交付。现在每项都对应可复查例子，并分别记录工程验证与人工试玩。主代理已执行内核、类型、构建和浏览器校验；最终状态及报告见本文末尾的整合表。自动检查不代表真人体验已通过。

状态写法：`待实现`、`已实现待验证`、`工程验证通过`、`需人工验证`、`范围待裁定`。打勾必须附证据位置；单元检查、自动浏览器操作、录屏不能替代真实试玩者。

## 第一版明确范围

§12、§16 与 §24 是首版范围的直接依据：一个事件“邯郸之战与窃符救赵”，约十个关键角色，主作品《窃符》约十分钟，加同一事件的其他作品、片场与最小导师。§24 已替定的选项在未被明确推翻前是当前设计选择；其中史料数字仍需按原典校验。

## 需要真实人参与的验收

这些条件是首版完成体验验收所需的门槛。当前没有真实试玩记录，必须保持 `需人工验证`，不能把研发者走通流程或自动脚本写成“已找五人验证”。

| 编号 | 需人工验证的事 | 设计出处 | 证据与通过线 |
| --- | --- | --- | --- |
| P01 | 找3至5名实际试玩者；观察3分钟内是否进入状态、是否理解换人、反转与历史转向 | §21 | 保存匿名试玩编号、日期、所玩版本、实际路线和原话；至少3人想知道后来，至少3人能说出两个人的差别。人数不足则未完成。 |
| P02 | 心智入口能否帮助解释差异；能否指出说法是谁信、从哪里听来；反转是否让人觉得有来由 | §21、§23.4–23.6 | 请试玩者口述原因，不先告诉答案；记录“像普通分支剧情”反馈。多数人如此判断时，应回头加强心智与主张图，不能按工程检查通过放行。 |
| P03 | 历史转向是否动情、是否追问人物下场、是否愿意再玩；约10分钟与短作品节奏是否合适 | §16.4–16.5、§21 | 记录实际用时、停顿、追问与重玩意愿；不能把预设的十分钟时间表当成实测时长。 |
| P04 | 史料解释、视觉时代规范、器物／服装／建筑的出处与使用权由人审定 | §4、§14.3、§16.7、§19.5 | 记录审定人、源版本、采用结论和争议。原典正文阅读已完成若干项，不等于考古外观审定已完成。 |
| P05 | 真实算力上限与云端调用费用、延迟、降级体验 | §8、§20、§24 | 用实际上线网关的调用账单／计数测量；固定离线演示只能验证降级路径，不能证明真实云端预算。 |

试玩记录可采用一行一人的结构：`匿名编号 / 日期 / 版本 / 完成路线 / 用时 / 对两人差异的原话 / 对反转的原话 / 是否想知道后来 / 是否愿再玩 / 观察者`。示例结构不填虚构人名、假反应或假统计。

## 草案内需要裁定的口径

这些是设计稿之间的具体张力，保留问题与建议，避免悄悄把全部远景变成首版需求。

1. **约10关键人物与约20人／12动词／一年时钟**：§12、§16 指向首版具体作品；§19.7 指向世界内核成长基准。建议当前按前者完成作品，后者作为独立扩展验收，不能仅凭少量首版角色宣称20人全年基准通过。
2. **“解围结构牢”与“取符断链可能陷落”**：§16.3 两种描述需落实条件。应声明本作反事实模型考虑哪些援军和不可替代环节；S76 记录了楚援与城内突击，不能把真实历史压成只有兵符一条因果。
3. **场景5至10分钟与整作10分钟由几场组成**：§23.8 与 §16.4 时间表不一致。建议以主作品约10分钟和明确节拍为当前节奏，实际测时后再细化一场定义。
4. **导师在首版范围内但路线图排在P5**：§12、§23.2 与 §22.1 排期不同。最小三档／笔记属于首版；完整导师排片和发布属于之后，不能用排期把最小笔记从成品中删掉。
5. **语言随时可用与按场授予三档**：§7 允许看不见、选一句、自由说三档。首版可以以选句和物件做主路，须明确各场授予；未接通自由语言时不宣称可以任意对话。
6. **精确纪年与地点异文**：§16、§24 的十七个月与前258起点尚未核定；邺／荡阴均有原典。当前使用相对时间和带出处的邺主线，不把异文直接删成错误。
