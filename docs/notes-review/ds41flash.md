### 11. v2：呈现＝视角（L183–L241）
- L183–L204 机器是独立心智之物；**"呈现机器的注视，呈现世界的材质签名"**；不要一个连续空间，信息通过**组件细节**呈现；不是无限画布而是像页面一样可滑动，导师可设计编排（重要的事放前面，控制组件大小/亮度/位置/动效）；组件细节呈现世界信息（边缘青铜器纹理代表春秋战国）；进入世界首先遇到的是**"呈现出来的世界"，关键就是呈现**；**所谓世界本质是一组基于设定/约束后的生成，而呈现方式也是一种约束**；**所谓呈现是一种视角**（世界内角色 / 世界外现代人 / 虚构）；导演构建角色**基础结构**，角色和世界一样成长；导演负责世界的呈现成品；导演和导师都应有各世界数据访问权限与一套工具；导演也**通过呈现去感受世界**（这是他了解读者的方式）；呈现方式＝用户与"机器里渲染的关于世界信息的画面"的交互方式，包括游戏/电影/网页且**可互相嵌套**；进入世界以**身体形式**行动是基础呈现方式；呈现就是**某个视角的摄像头**，把元素组织在一个空间，2D/3D 都从某视角采集；视角分**隐形/非隐形**（非隐形能被附近角色感知）；摄像头也只是其中一个约束；**导演最终交付的是呈现而不是世界**；交付前可反复调整，**交付后它代表某种事实就不能再改**；后一个作品应基于之前所有作品的事实、考虑时间流逝后的世界事实；导演应意识到他做的所有作品，会不断突破自己并对自己的历程形成自我解释。

- L216–L218 好玩性设计方法之一是控制新老体验**潮汐式**推进；为逐渐深入必须**不断转换视角**；玩家沉溺一个视角时需**渐强提醒**（情景内提醒 → UI 提醒）。
- L221–L223 第一层看**导师管理机器、指导构建多个世界**，第二层看**导演构建世界的呈现**，第三层才是**选择的呈现方式**；这是**创作性 AI**——不是构建一部作品，而是构建一个"构建世界的 AI"；得到呈现之前世界不固定，只是约束。
- L226–L232 不是所有事情都需要装置（装置只为提高可玩性，不可过度）；导师和导演都是高级心智，**需要在界面可见其行为甚至决策（默认折叠）**；注入血肉的机制：LLM 搜集资料或用户直接放资料 → 生成世界设定/约束（**一个咨询角色**，按导演意图设计历史框架）；导演发布前调整作品时要**跟演员讨论**；工程问题：三层经验不断增长，需管理可扩展的上下文；需要各角色之间的**信息传递机制**（自洽、无盲区、面向用户体验）；导演组织的呈现方式即用户交互方式，用户交互首先影响世界，**交互数据沉淀给导演、导师去设计下一个世界**。

### 12. v3：时间线与"扮演程度"（L246–L252）
- L246 导演设计的呈现视角与提供给玩家的控制**应一致或有一定理由**（电影里不能行动与镜头客观性一致）。
- L248 人脑里有时间线，**导演呈现的作品是时间线的重新组合**；导演脑里的时间线与用户不一定相同；作品之间矛盾也行，只要有更深设定支撑；关键的**不是事实，而是用户如何理解事实**——机器的呈现与用户的历史之间的交融才是关键。
- L249 **用户扮演角色的程度不是 0/1，还可以是 0.3**（只控制部分）。
- L250 导演应有**量化标准**、朝标准行动，有**停止准则**，且停止准则也是标准的一部分、会迭代。
- L252 呈现作品先从历史类游戏做起；目标体验可注入导演思想（发布后应由**导师给主题**）；历史游戏目标体验锚定两点：**征服 / 历史情景**。

### 13. 心智结构条文（L256–L259、L292–L306）
- **L256** 关键不是体内环路，而是**人由众多基本单元搭建**；最重要的是**感知**（空间、温度等）；感知多了就需要决策，所以**有心智、有记忆机制（如艾宾浩斯遗忘曲线）**；所有感知模块与记忆模块持续运作；**人的行动本质是感知单元的空间移动**；体内也有单元负责分配资源；**心智是最高层的感知**，底层信息它不知道（哪个细胞毁灭它不知道），只知道人体在环境里的整体信息；因为任何单元的共性在于**预测误差-行动反馈-参数调节**；**反馈反应、前馈控制、模型预测是基本单元的三大反应**；单元之间交流，基于共同目标产生高一层模块，高层模块更关注高层信息、负责调节整体；心智也是这样产生。
- L257 怎么让角色持续存活：信息输入角色后启动**预测误差传递**，向关联单元传递，**最终可能传到心智也可能不**——仅由底层模块/单元解决。
- L259 本产品关键是**角色与环境的交互**：最外层环境是**机器上的文件与计算资源**，角色是**导师**；然后是**导演**（环境主要是它构建的呈现世界 + 众多导演共同生活的世界；导演与演员最大不同是**能多个视角**）；第三种是**演员**（与世界交互）；其他工种暂不需完整心智，现在归属于这三种角色管理。
- L261 本质是**将游戏体验拆散，变为一个个呈现**。
- L292–L293 一个呈现只是对世界发展做了**约束**（约束内某些事情发生有更大可能性）；呈现必然经过**视角过滤**；一个视角的本质是**相信世界如何运转、别人如何行动**；**所谓心智模型就是如何设想别人如何行动**；用自己的结构构建别人的结构，不是完全重构，只按需要构建某些场景里的结构；**算力越高的人，能构建的程度就越高**。
- L295 心智结构条文重复（含艾宾浩斯遗忘曲线、预测误差-行动反馈-参数调节、三大反应）。L296 心智结构也不是一下得到，是在**角色和环境共同进化**中进化。
- L300–L306 用心智结构让一个人**设想另一个人会怎么做**；这个设想过程属于心智活动之一，可与其他事情交叉，**设想的经历会沉淀**；**LLM 在这个机制中的作用**：① **以超出当前可行动集合的方式行动**（当前环境不提供的行动可以用代码改造当前环境，改造的必要性与方向另外提供——这就是角色与环境的共同进化）；② 充当**翻译**（在机器外面一层，以人类语言材料操控机器内某一层，或把某层的事情翻译给人类）；**只有 agent 有心智模型，才谈得上 AI 创造游戏**；L308 构建一个**能自我认知、产生问题的环境**。

### 14. v5：三层视野与三个重点（L265–L288）
- L265–L270 首页看到最重要信息：重点关注的世界及其导演、导师在处理的事情与接下来规划、最近机器上发生的重要事；能去另一个场景看**资源账本**；导演的世界入口是**跟随导演的存在**（如咖啡馆里他旁边的一幅海报）；第一层环境由某导演构建、也受导师约束，**导师是手握资源即权力的人**；进去后是**一个个呈现**，排列可为一套 UI（如架子上），可看作个人资源库；呈现意思是用户可以进入与世界交互，**看电影也是一种交互**（只是不需鼠标键盘）；**一个呈现就是某个人的视角看那个世界**；**导师那层称外层，世界这层称中层，呈现里的那层称低层**。
- L271–L272 内置一些游戏框架方便快速构建，后续应支持**无限增加框架**及在产品内按用户需求**增删改**；作品有**介绍入口**介绍其元素（音乐、交互方式、按键效果、成就等），但**不是所有元素都披露，有些需解锁**。
- L273–L277 重点 1 **多种呈现的交织**（呈现与世界的深入有关，即持续共同进化；呈现 / 用户偏好数据 / 探索世界可能性 / 新的呈现；每一次呈现都赋予环境和角色一些约束，也给导演和导师一些经验）。
- L278–L283 重点 2 **角色与环境的持续共同进化**（导师、导演、演员都是角色，导师和导演联合创造环境与演员的生长规则；**角色有心智加分，有可视化、可交互的心智满分**）。
- L284–L286 重点 3 **新的游戏呈现方式**（目前重点历史-RPG，类似太阁立志传；**角色处在什么位置决定其能感知什么、做什么、以及用什么方式理解问题**）。
- L287 找一个**多模态聚合工具**（暂时用 litellm）方便后续资产生成。
- **L288 角色的核心是 LLM 打造一个适合它与环境交互的 Harness。**

### 15. v8：折叠与更高抽象（L310–L312）
- **L312 任何呈现都可以被折叠，不断追求更高抽象。**导演/导师的资源调配过程开头可能饶有趣味地看，后面就不再那么需要，只在**有特殊变化时**才看。背后的思想是：不断有别的方式**压缩现实**，**用更少的注意力关注更高层的信息**；**底层信息只要需要，就能随时重建**。

## 三、缺口清单（按"对产品方向的影响"从大到小）

### 缺口 1：多尺度分辨率整块缺失（L44–L51）
- **是什么**：仓库有"按一场分档位"的算力分配（`shared/kernel/depth.js:14-21`、总稿 :145-149），但**没有"世界以低分辨率持续演化、聚焦处才提高分辨率、人群街道从统计结构显影"这一层**；`分辨率`/`低分辨率`/`高分辨率`/`resolution` 在任何设计文档与 shared/ 代码里都是 0 处。L45 的硬边界（被低分辨率模拟过的过去不能后来假装曾高分辨率模拟过）也完全无对应物。
- **为什么重要**：这是 note1 里**唯一同时决定"体验感"和"可信度"的机制**。"重新提高分辨率、从统计结构显影"是 L44 描述的最好的一个体验结果；L45 的边界又是"数字世界是否可信"的底线。缺了它，"导师分配算力"就只是选精细度，而不是"世界在什么分辨率上真实存在过"——note1 的命题（有限机器里的存在怎样获得连续性）没有承载物。
- **影响哪些模块**：`shared/kernel/depth.js`（档位→需要变成分辨率）、`shared/life/life.js`（逻辑拍推进需要能跑低分辨率世界）、`shared/engine/session.js`（存档需要记"某段历史是在什么分辨率下发生的"）、`docs/数字世界 设计总稿 v3（草案） (2).md` §8（导师与算力）、`docs/design/LIVING.md`（"不承诺后台世界推进"这句要重写）。

### 缺口 2：目标与终局只剩"固定终局"，内生目标与不可逆承诺都没有（L98–L107）
- **是什么**：六方案里只落了方案 1 的一半（三结局）：`goals` 是 `shared/data/seed.js` 的静态标签（唯一用法 `shared/core/mind.js:111` 加权），没有任何运行中改写（方案 2 无）；没有玩家目标编译（方案 3 无）；没有 goal proposal 生命周期（方案 4 无）；`不可逆`/`commitment` 全仓库 0 处，CHAIN 的 `mutable:false, irreplaceable:true`（`shared/data/seed.js:497,537`）**只有测试在读**（`tests/mind.test.js:5,14,15,16`）（方案 5 无）；方案 6 部分（`mind.imagine`＋心智入口＋`director.predict`）。
- **为什么重要**：note1 L107 把"目标"直接放进动态系统（`gameplay → emergent goal → commitment → new gameplay`），并且 L104 给了明确的体验判据——**"生成内容可以无限，但真正重要的东西必须越来越少、越来越重"**。这是"AI 原生游戏"区别于"AI 生成更多任务"的分界线（L107 原话）。现在仓库最像 AI 原生的部分（持续生活、自主行动）与"终局"之间**没有连接件**：玩家越玩，世界越活，但重要的事没有变重。
- **影响哪些模块**：`shared/core/claims.js`（overturn 已是不可逆单点，需要升级为承诺累积）、`shared/data/seed.js` CHAIN（不可逆字段要接进运行时）、`shared/agents/director.js`（design/learn 要能改目标与承诺）、`shared/agents/mentor.js`（分配要能对"更重要的事"加码）、`shared/life/plan.js`（policy 需要面向承诺的阶段，而不是只有逐拍）。
