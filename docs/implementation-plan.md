# 数字世界第一版实施计划

需求依据：`数字世界 设计总稿 v3（草案） (1).md`，2026-10-11。

## 交付边界

实现文档第 12、16、24 节规定的第一版。仓库中没有 units.js/mind.js 或既有应用，采用可审计的有限状态心智，从零建立可运行产品。完整科研、游历、多世界、自动生成任意游戏和真人 3–5 人访谈不伪装成已完成。真人访谈提供操作脚本与记录模板。

## 产品与验收

- 《长平之后》：零交互开场，暂停/继续/跳过，结束递出进入《窃符》的按钮。
- 《窃符》：大梁、夷门、取符之夜、邺城、结尾五段；以物件选择和场景互动推进；史实与本作历史分开。
- 《围城》：印信、借条、担保物的交接；两个视角；换守仓人看到心智和行为变化；至少五次交接；共享世界留下后果。
- 《取符之夜》：独立可玩的潜行，键盘、点击地面和触控一致；遮挡、守卫视锥、兵符、出口；被发现也产生后果。
- 片场：读真实决定记录；导演椅随认可解锁，下一场选角可操作；带条件的预制段落与降级。
- 导师笔记：三个粗问题冷启动、偏好可更正、三个实际调用档位、上限后规则接续，决定当下记录。
- 角色维基：人物、关系、信念来源、曾经的共识、性情/手艺与经历分离；看心思读实际轨迹。
- 主张图：结构化持有者、渠道、原文出处、认可、依赖、引用；冲突分档；反转需证据/解释/批准/下游重算。
- 内核：实体与 12 个数据驱动动词、四类资源、一年时钟与回访补算；角色视野隔离；确定性回放。
- 改造链：结构化轨迹触发，声明式机制静态核验、隔离对照、至少 20% 协调成本下降、安装/回滚、离线复用；不执行模型任意代码。
- 模型：服务器侧兼容 LiteLLM 的能力路由、缓存、输入输出录制、实际用量与时延、规则降级；云调用未经配置时明确显示离线录制模式。
- 资产：程序化 2.5D 场景、统一人物包、原创规则作曲与音效，全部有编号/版本/来源/许可；视觉史料待人审定。
- 保存：本机服务器 SQLite 持久化、浏览器会话识别、乐观版本防覆盖；导出/导入、旧版本迁移与显式重置。

## 阶段与可复验例子

1. 契约与内核：同样缺 2 袋粮，多疑者核印信，急躁者追借粮者。
2. 场景与叙事：进入《窃符》，递竹简，侯嬴是否献计取决于记录下来的认可。
3. 多作品共用：潜行取符后，在另一作品/角色维基看到同一个事件的证据。
4. 反转与成长：揭示账册错记，旧主张保留为曾经的共识；机制安装后第二次核验步骤减少。
5. 测试与发布：类型、内核、API、生产构建、浏览器真实输入/移动端/保存重开/两个结局/异常降级。提供验收报告和运行入口。

## 视觉与交互

战国漆木剧场：墨靛 #142b35、漆木 #443934、青铜 #749f91、淡金 #d8bd7b、骨白 #f1eada、雾蓝 #91a4ab。展示字用中文宋体，操作字用中文黑体；左对齐短文，竖排作品标题，主作品大场景、次作品小册页。移动端一屏一个重点，人物和器物优先于面板。

核心循环：观察场景 → 长按/点人物理解心思 → 递物或一句粗意图 → 人物按心智回应 → 写成主张 → 后续作品引用 → 结尾成为自己的电影。
潜行为确定性二维地面运动与遮挡检测，Three.js 投影；无需刚体引擎。
