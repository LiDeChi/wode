## 潜行场景的可玩性返工（取符之夜）

触发是单人试玩的一句话：「只能走来走去，还没有任何技巧或者乐趣，而且都没有偷或者拿的動作可用，只能移動」。核查后这句话对**仓库里已提交的那一版**字面成立：`d545cfa` 的 `src/game/night.ts` 只有 84 行，走过石台 0.65 之内就自动把兵符算作到手，守卫被看见时既不转身也不追人，被发现只让一条暴露条以 0.17/s 上升、看不见时以 0.38/s 回落。取符（按住 E）、掷石（Q）、蹲行与疾行只存在于本工作区未提交的改动里，所以能玩到的版本确实没有「拿」这个动作。

改造前的实测（60 个起始相位，每段都晚 N tick 驱动真实模拟）：

| 每段晚 | 干净 | 被发现但逃出 | 被抓 |
| ---: | ---: | ---: | ---: |
| 0.00–0.30 s | 60 | 0 | 0 |
| 0.40 s | 56 | 0 | 4 |
| 0.50 s | 3 | 0 | 57 |
| 0.60 s | 56 | 0 | 4 |
| 0.80 s | 0 | 0 | 60 |

把网格加密到一 tick 后形状更清楚：0.40 s 仍 56/60，0.43 s 掉到 2/60，0.43–0.57 s 整段只有二到五条活得下来，0.60 s 又回到 56/60。也就是说「晚多少」并不平顺地映射到结局，而是由撞上守卫巡逻相位决定；B 的周期是 2π/0.32 = 19.63 s，而每段都晚 N 会让整条路线平移约 13N 秒。失败取证显示损失集中在同一处：玩家停在（1.79,−4.60）等哨，被先前脚步引来的守卫走近到 0.36 并把视锥压在他身上，而退路上没有任何挡视线的东西，警觉衰减因此从不触发——一次被看见就等于这局结束，玩家没有可做的决定。

修复（`src/game/night.ts`）：每个守卫保留自己巡逻线的中心作为「岗位」，被引离岗位超过 `LEASH`（A 4.2 米、B 2.7 米）且尚未确定是你时，他放弃追捕走回岗位，视线随之离开玩家。作用域是重点：巡逻中的守卫按构造总在岗位范围内，所以这条规则只可能在追捕中生效，**站在本职守卫正前方不动仍然是必被抓**，`tests/playability.test.ts` 单独固定了这一点。也曾试过「玩家安静下来守卫就失去线索」的写法，那会让静止变成全局免罪符、并使画出来的视锥说谎，因此没有采用。

改造后同一张表：0.30 s 为 60/0/0；0.40 s 为 56/4/0；0.50 s 为 3/**57**/**0**；0.60 s 为 56/4/0；0.80 s 为 0/0/60。**0.30–0.60 s 整段的「被抓」归零**，原本失败的每一次都变成「被看见但带着兵符回家」。四条路线对照（改造前 → 改造后）：谨慎 60 干净 → 60 干净；站着取符 60 干净 → 60 干净；带符疾行 0 干净／60 被抓 → 不变；完全不读守卫 8 干净／5 被发现／47 被抓 → 6 干净／4 被发现／**50 被抓**。惩罚没有被买回来，反而略升。

仍未做到：干净（未被发现）那一列仍然非单调，0.43–0.57 s 只有二到五条能全身而退。也就是说「能不能不被看见」仍由相位决定；改变的只是它不再决定这一局是赢是输。0.63 s 起仍然 60/60 失败，但换成另一个原因——晚太多会冲过石台，取不到兵符，这是一条真实的技巧边界，没有被修掉。

可复现下限（`tests/playability.test.ts`，12 个起始相位，真实模拟驱动，约 0.2 秒跑完）：读守卫、每段都晚 0.2 秒 → 12/12 干净；不看守卫直冲 → 11/12 被抓；0.5 秒档 → 被抓不超过 2、11/12 以「被发现但逃出」收场；站在本职守卫正前方不动 → 仍然被抓。

### 手机上的方向键曾经按不动（验收发现，已修）

把蹲行／疾行／取符／掷石放到手机底部之后，验收跑出一个**可稳定复现**的失败：`[mobile] product.spec.ts`「暂停后继续，角色必须真的能动」等待 15 秒超时。取证不是猜的：在同一坐标做命中测试，指针落到的不是方向键，而是 `DIV.toast`。状态提示条是 `position:fixed; z-index:50; bottom:25px`、宽度几乎铺满，在 390×664 的手机上正好压在移动方向盘上；它存在 5.5 秒，这 5.5 秒里右边的方向键是死的。键盘（WASD）不受影响——所以只有用手指按住屏幕方向键的玩家会撞上，而真人手机玩家正是这样玩的。

**这不是本轮新引入的规则问题**：`.toast` 规则与已提交的 `d545cfa` 逐字相同，是旧有的；本轮只是把触摸方向盘放进了它原本就占据的那条带子里。上一轮验收之所以是绿的，是因为那一次跑到「按住」这一步时提示条已经自己消失——一个按时间碰运气的绿，不是一条通过的保证。

修法是让提示条不接收指针事件（`pointer-events:none`）：它是 `role="status"` 的纯文本，全仓库没有任何点击处理挂在它身上，本来就不该吃掉点击。另加一条不依赖时机的回归检查 `a status toast never swallows a tap meant for the movement pad`：主动往页面里放一条真实尺寸的提示条，再问浏览器「手指按在方向键中心，实际摸到谁」，断言摸到的仍是方向键本身。断言的是后果而不是 CSS，所以将来重新排布或改样式都仍成立。修后同一坐标命中测试返回 `BUTTON aria-label="向右"`，按住 0.5 秒角色即开始移动。

仍未做：手机上的提示条依旧会**视觉遮挡**方向键约 5.5 秒，本轮只修掉「吃掉点击」，没有改版式。
